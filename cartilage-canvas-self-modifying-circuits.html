Open Cartilage Canvas

The Texture Is The Program And The File

Cartilage Canvas does not mirror a circuit into browser storage. Its local file contains one current source texture, the fabric dimensions, the native ownership-format identifier, and the pan and zoom view. Open parses that texture into the running fabric. Save serializes the current source texture into a downloadable JSON file that can be opened again.

One current plane

The file carries the current causal source plane, not a second hidden circuit model or a JavaScript annotation database.

Ordinary local files

Open uses the browser file input. Save uses a Blob download. IndexedDB, localStorage, sessionStorage, and server persistence are absent.

Works from disk

The HTML has inline CSS, JavaScript, shaders, examples, and initial textures. Its content-security policy rejects network connections.

Save-defined geometry

Resize adds or removes complete 4×4 blocks on any side. Geometry belongs to the file rather than to a numbered example slot.

The causal rule remains simple: one complete source texture is read-only, one complete destination texture is write-only, and every animation frame flips them once. Direct editing queues a patch for that ordinary transition. The fabric never halts.

Names Live In The Same Bits As The Circuit

Runtime reflection is not a JavaScript ID map laid over anonymous cells. Every native 4×4 block contributes four metadata bytes to its reconfiguration-port-rooted physical tree. Native postorder joins those bytes into one distributed local database. The renderer decodes that database from the current texture.

80 roles 16 snapshots 2 parent 3 walls 1 port 32 metadata

One native block record is exactly 134 bits. The final 32 bits are streamed and installed with every other field.

Physical object name

The port-rooted tree names the physical object that can be read or replaced through that port.

Per-cell signal name

A compact postorder ordinal plus local cell number locates a sparse signal label and its waveform flag.

Logical subregion

Run-length encoded postorder membership describes a named subdivision without creating another ownership forest.

Module instance

The same distributed stream can identify a named instance spanning selected blocks inside the one physical tree.

The decoder rebuilds a viewport-indexed rendering cache: visible row runs, exposed region boundaries, sparse cell labels, physical-root captions, and up to ten waveform names. Colors are derived deterministically from decoded names. They are presentation, not hidden authority.

Prototype Inheritance Is Homogeneous And Two-Dimensional

A source component does not need an edge-only loader or a JavaScript copy operation. Instantiated application MUXes and wires can read one source port-rooted tree and carry its native records to a target reconfiguration port anywhere the application wires reach. Multiple routed controllers can do this in parallel.

  1. Application wires reach the source port.
  2. The source tree emits native records in postorder.
  3. Every adjacent port remains a hard traversal barrier.
  4. Routed application wires carry the stream to one or more targets.
  5. One final edge applies roles, snapshots, ownership, ports, and reflection metadata together.

The entry block is an ordinary record, not a privileged root record. A final edge may reparent the old tree, split it into multiple new physical regions, turn every block into a port, or create an inaccessible cycle. Once the source metadata is installed, the target’s labels and region names appear because the texture changed—not because JavaScript recognized a particular example.

Debugging Watches Causal Frames Without Pausing The Fabric

Pin any decoded per-cell signal label to the expandable waveform dashboard. Home, rewind, freeze-trace, and step controls move through captured observations while the underlying fabric continues one causal transition per rendered frame. Up to ten reflected signal names remain visible beside their digital traces.

Shape, read, and write overlays also come from controller state in the just-swapped source plane. Cyan, blue, and amber decoration covers the complete participating 4×4 block. Traversal never decorates an adjacent port or anything behind it.

These checks separate three different facts: the substrate can transport native records; a host can drive an edge-visible port; and an instantiated circuit inside the fabric can perform the read-to-install sequence itself. The prototype examples are built for the third fact.
